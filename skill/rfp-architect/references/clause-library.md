# 台灣在地條款庫（可直接貼入 RFP）

這些是國際 RFP 範本通常沒有、但台灣委外案不可或缺的條款。write 模式視標的勾選貼入；review 模式檢查既有 RFP 是否遺漏。**請依個案調整等級、門檻與罰則數值。**

## A. 資通安全分級

> 本案系統依《資通安全責任等級分級辦法》附表九「資通系統防護需求分級原則」評估為【普／中／高】等級；得標廠商應落實對應等級之存取控制、加密、日誌稽核與弱點管理措施，並於各階段提供佐證。

- 分級越高，控制越嚴。涉及個資或關鍵業務者通常為中／高級；防護需求等級為高者屬核心資通系統（《資通安全管理法施行細則》），連動 S 節的第三方安全性檢測。

## B. 廠商資安資格

> 受託業務之相關程序及環境，應具備完善之資通安全管理措施或通過公正第三方驗證（如 ISO/IEC 27001），得標廠商並應簽署資訊安全承諾書與保密同意書。

- 法源：《資通安全管理法》§10 第 2 項。公務機關與特定非公務機關委外時另須簽訂書面契約，載明雙方權利義務及違約責任（同條第 3 項）；完整委外事項見 S 節。

## C. 禁用產品與廠商資格（台灣特有）

> 本案履約不得下載、安裝或使用危害國家資通安全產品（依主管機關認定）。本案涉及國家安全，不允許大陸地區廠商、第三地區含陸資成分廠商及經濟部公告之陸資資訊服務業者參與；分包廠商亦同。投標廠商應檢附資格證明文件，證明內容於投標後有異動者應主動通知機關。

- 產品限制的法源：《資通安全管理法》§3 第 11 款、§11（公務機關）、§27（特定非公務機關，由中央目的事業主管機關限制）。因業務需求且無替代方案者才可專案核定，招標文件不宜自行開例外。
- 廠商資格限制的法源：《政府採購法》§17 第 4 項與《機關辦理涉及國家安全採購之廠商資格限制條件及審查作業辦法》：機關得就廠商國籍、代表人與持股逾 10% 股東之國籍、資金來源等訂定限制，**應敘明理由及必要性，簽報首長或其授權人員核准**，並於招標文件載明及列出應檢附之證明文件（有分包廠商者亦同）。
- 履約人員限制依《資訊服務採購契約範本》與資通安全署〈資安檢核事項〉逐項選用，不要沿用未經查核的舊條文。
- 遺漏可能於審標爭議或履約後衍生資安事件；反之把限制寫得比法源更寬，可能構成不當限制競爭（《政府採購法》§37）。

## G. 智慧財產權歸屬（提供可勾選選項，勿留空）

> 本案履約成果著作財產權歸屬：☐ 由機關取得　☐ 由廠商享有、機關取得授權利用。
> 著作人格權：☐ 廠商保留姓名表示權　☐ 其他約定＿＿。
> 履約成果侵害第三人合法權益時，由廠商負責處理並承擔一切法律責任。

- **這是應載事項**：《機關委託資訊服務廠商評選及計費辦法》§21 要求招標文件規定成果之智慧財產權歸屬及侵權責任；機關得視需要取得部分或全部權利或取得授權。
- 原則：無特殊目的（國家機密 / 資安 / 高度客製）時，宜由廠商享有、機關取得授權（促進流通、降低成本）。需完整取得時於契約明確約定。
- **素材權利**：成果含音樂 / 圖片 / 影片片段時，須另取得公開傳輸 / 公開播送 / 公開上映授權；要求廠商驗收前提供授權書、著作財產權歸屬約定書（含其與員工之約定證明）。
- **分包著作權鏈條（最常落空、最難事後補救）**：得標廠商若聘第三方（分包商）協助完成履約標的，須於契約約定其**負有義務**替機關向該第三方取得授權或受讓著作財產權，並於決標 / 簽約日起一定期間（建議 10 日）內，將授權書、著作財產權歸屬約定書、讓與書等證明文件交付機關收存。**員工約定無法涵蓋分包商，須另立條款**——曾有機關取得得標廠商著作權，卻因部分程式由第三方完成、第三方未讓與，致無法取得完整著作財產權。將契約全部或主要部分交由他廠商代為履行屬轉包，勞務契約不得轉包（《政府採購法》§65）。

## I. 變更管理與變更請求流程（在 RFP 階段就先講清楚）

> 履約期間之需求變更應依正式變更請求（Change Request）流程辦理：提出者填具變更單，載明變更內容與原因、對範疇 / 時程 / 成本 / 風險之影響評估、不變更之後果與替代方案，經雙方變更控制窗口書面核准後始得執行；未經核准之變更不納入履約範圍。

- 變更請求分兩類：**範圍內變更**（客戶主導、原契約涵蓋）與**範圍外變更**（須另議時程 / 報價）。RFP 階段就揭露此流程，是抵禦範疇蔓延的核心機制。
- **為何放進 RFP**：委外失敗的首要根因是需求模糊與不受控的範疇蔓延；事前未約定變更流程，後期任何「再加一點」都會演變成延誤、超支與爭議。

## J. 退場、資料返還與移交（contract exit / transition-out）

> 契約屆滿、終止或解除時，廠商應於約定期限內：(1) 以雙方議定之開放格式完整返還機關所有資料與衍生資料，**並於返還確認後刪除 / 銷毀廠商端所有留存副本（含備份）並出具刪除 / 銷毀證明**，且不得保留或主張資料留置權；(2) 提供系統原始碼 / 設定 / 部署文件 / 維運手冊（依智財歸屬約定）；(3) 配合辦理知識移轉與服務移交，協助後手廠商或機關自行接管，確保服務不中斷。退場 / 移交之範圍、期限與配合義務應於契約明定。

- **為何放進 RFP**：缺退場與資料返還條款，機關易被廠商以資料 / 原始碼「綁架」，造成更換廠商困難、議價弱勢；CLM（契約生命週期管理）最佳實務要求把退場與資料返還條款前置設計。公部門與關鍵系統尤須具備。
- **法源**：《資通安全管理法施行細則》§7 要求委託關係終止或解除時確認受託者返還、移交、刪除或銷毀資料；《個人資料保護法施行細則》§8 要求監督事項含個人資料載體之返還及儲存資料之刪除。

## K. 專案治理與供應商盡職調查（把失敗預防框架寫成可投標條款）

> 機關側應指定產品負責人與技術窗口，並設能於【24】小時內裁決之專案發起人；履約期間採固定溝通節奏（每日 / 每週進度同步、共享專案管理工作區）。投標廠商應於建議書中：(1) 提出將**實際參與本案**之團隊名單、角色與資歷（非僅銷售或掛名人力）；(2) 視標的規模配合概念驗證（PoC）或啟動期付費技術評估，再進入完整開發。

- **為何放進 RFP**：常見失敗是「以精緻提案與低價得標，實際指派資格不足團隊」。要求揭露實際團隊、安排 PoC / 技術評估、明定甲方決策窗口與溝通儀式，能把治理從事後補救轉為投標即可檢核的條款。

## L. 計費方式與費用結構（資訊服務委外｜《機關委託資訊服務廠商評選及計費辦法》）

「計價及付款方式」列於 §5；服務費用計算方式應訂明於契約（§13），各次付款金額及條件應予訂明（§19）。本辦法提供三種法定計費法及硬上限，與國際 Fixed-Price / T&M / Cost-plus 一一對應。**請依個案於招標文件與契約擇一訂明。**

> 本案服務費用採下列方式之一（於契約訂明）：
> ☐ 總包價法 / 單價計算法　☐ 按月 / 按日 / 按時計酬法　☐ 服務成本加公費法

- **總包價法 / 單價計算法**：適用工作範圍及內容**明確**、總價可正確估計或可按單價計算者。（對應國際 Fixed-Price；範圍鎖定時用。）
- **按月 / 按日 / 按時計酬法**：適用工作範圍小，或範圍 / 內容**無法明確界定**、總費用難以正確估計者。（對應國際 Time & Materials；範圍模糊時用。）
- **服務成本加公費法（§16）**：適用計畫性質複雜、費用不易確實預估或**履約成果不確定**者。費用＝直接費用（直接薪資＋管理費用＋其他直接費用）＋公費＋營業稅，並受下列**法定上限**：
  - 管理費用**不得超過**直接薪資（扣除非經常性給與之獎金後）之 **100%**。
  - 公費應為**定額**，不得按直接薪資及管理費之金額依一定比率增加，且**不得超過**（直接薪資扣除非經常性給與之獎金＋管理費用）之 **25%**。
  - 工作人員不扣薪假與特別休假之薪資費用，得於招標文件明定為實際薪資之一定比率，**不得超過 16%**；非經常性給與之獎金得明定比率並檢據核銷，**不得超過 30%**。
- **採成本加公費法時契約應訂明（§18）**：廠商記錄各項費用並提出憑證、機關得至廠商處所查核；**成本上限及逾上限時之處理**。
- **獎勵性報酬（§17，採成本加公費法時得約定）**：費用降低者，給付不逾所減省契約價金之 **50%**；績效提高者，給付不逾契約價金總額（或上限）之 **10%**。
- **預付款（§19）**：以不逾契約價金總額或上限之 **30%** 為原則。
- **物價調整（§20）**：履約期間一年以上者，得於契約訂明自第二年起隨物價指數調整契約價金，並敘明調整項目、方式及金額上限。

> **選擇準則**：範圍明確 → 總包價；範圍模糊 → 計時；成果不確定 → 成本加公費。大型探索性案件可採混合（探索期固定價、建置期計時、按里程碑付款）。所有數值（100% / 25% / 16% / 30% / 50% / 10%）以全國法規資料庫最新版為準。

## M. 個人資料處理與事故通報（個資法遵）

僅寫「依個資法辦理」不可執行。應於 RFP / 契約具體載明：

> 廠商處理本案個人資料應遵循下列要求：
> - **資料類型與處理目的**：明列蒐集之個資項目、處理 / 利用目的，且不得逾越目的必要範圍（最小必要原則）。
> - **存取控制與留存**：以最小權限原則控管存取；明定資料留存期間，逾期或目的消失後依約刪除 / 銷毀。
> - **委託處理義務**：廠商為受託者，應依個資法及主管機關規定為適當安全維護；再委託（分包）須經機關書面同意並課以同等義務。
> - **事故通報時限**：發生個資被竊取、竄改、毀損、滅失或洩漏等事故時，應於約定時限（建議 72 小時內，並依機關內規）通報機關，協助查明、通知當事人及採行補救措施。
> - **機關監督**：機關得保留指示事項，並定期確認廠商執行狀況及記錄確認結果，廠商應配合。

- **法源**：受託者於個資法適用範圍內視同委託機關（《個人資料保護法》§4）；委託機關應為適當監督，至少包含：預定處理之範圍、類別、特定目的及期間；受託者之安全維護措施；複委託之對象；違反法令時之通知及補救；保留指示事項；關係終止時載體返還與儲存資料刪除；並應定期確認及記錄（《個人資料保護法施行細則》§8）。
- **法規時效提醒**：《個人資料保護法》民國 114 年 11 月 11 日修正條文（含第 12 條事故通報、個資保護長、個人資料保護委員會）已公布，但施行日期由行政院定之，查核日 2026-10-31 全國法規資料庫仍標示尚未生效。通報範圍與時限待子法訂定，上開 72 小時是契約約定建議、不是法定時限；引用具體條號 / 罰則時應標註版本與查核日，並提示由機關法務確認。

- **適用情境**：涉及大量個資、機敏或關鍵基礎設施之系統，資料落地與跨境揭露宜列為 Blocker 級要求。

## O. AI 系統條款（生成式 / 預測式 AI、模型類服務）

採購含 AI / 機器學習之系統時，僅寫「導入 AI」不可驗收。應於 RFP / 契約具體載明：

> - **錯誤與幻覺控制**：揭露錯誤率 / 幻覺率量測方式與可接受上限；高風險輸出（法律 / 財務 / 個資）應有**人工覆核（human-in-the-loop）**流程與可追溯紀錄。
> - **輸入資料治理**：機關輸入之資料、prompt、對話紀錄**是否用於模型訓練 / 微調**（原則不得，例外須書面同意）；prompt / log / 對話之保存期限、存放位置與刪除機制。
> - **公平性與可解釋性**：對影響民眾權益之決策，要求偏誤（bias）評估、公平性檢核與可解釋性說明；保留稽核軌跡。

- **為何放進 RFP**：AI 採購的不確定性高，宜採**結構化 PoC / 付費技術評估**（連動 K 節）先驗證可行性與評估指標，再進入完整開發；評選須採**一致評估量表**避免各廠商自說自話。不得在 RFP 臆造模型效能數值，以「待驗證指標」標記。
- **公部門依據**：《人工智慧基本法》（民國 115 年 1 月 14 日公布施行）要求政府使用人工智慧執行業務或提供服務應進行風險評估、規劃風險因應措施，並依業務性質訂定使用規範或內控管理機制；其原則含人類自主、隱私保護與資料治理、資安與安全、透明與可解釋、公平與不歧視、問責。機關另應對照《行政院及所屬機關（構）使用生成式 AI 參考指引》。上列條款可把這些義務轉成廠商交付物（風險評估資料、稽核軌跡、人工覆核流程）。

## P. 資料治理條款（資料平台 / 資料倉儲 / 跨系統整合）

涉及大量資料蒐集、清理、整合或開放之系統，應要求可治理、可追溯：

> 廠商應提供並於契約維護：
> - **資料字典（data dictionary）與資料血緣（lineage）**：欄位定義、來源、轉換邏輯與流向，確保可追溯與可交接。
> - **資料品質 SLA**：完整性 / 正確性 / 即時性之量化門檻與量測方式；不達標之處理。
> - **權限矩陣（access matrix）**：以最小權限原則定義角色與資料存取範圍，定期審查。
> - **去識別化 / 假名化**：對外提供或分析用途之個資，依目的採去識別化 / 假名化，並評估再識別風險（連動 M 節）。

- **為何放進 RFP**：資料治理缺漏會在上線後才爆發（資料對不上、無法稽核、交接困難）；事前要求字典與血緣，是退場可交接（J）的前提。

## Q. 雲端韌性與營運持續（RTO / RPO / DR / 金鑰）

N 節揭露資料**在哪**；本節要求服務**斷得掉、回得來、鑰匙誰管**：

> 廠商應於建議書承諾並於契約量化：
> - **RTO / RPO**：各關鍵服務之復原時間目標（RTO）與資料復原點目標（RPO）數值。
> - **BCP / DR 演練**：營運持續與災難復原計畫，**並定期實地演練**（如每年至少一次）並提供演練報告。
> - **金鑰管理**：加密金鑰之管理方式（KMS / BYOK 自帶金鑰 / HYOK），機關對金鑰之掌控程度；委外不得使機關喪失對自身資料之解密控制權。
> - **備份不可竄改性（immutability）**：關鍵備份具防勒索 / 防竄改特性與保留期；備份還原需定期驗證。

- **適用情境**：關鍵業務、對外服務、涉個資或金流之系統，RTO / RPO 與 DR 演練宜列為必要要求；缺之屬 Major 以上。

## R. 開源與供應鏈安全（SBOM / 授權 / 弱點）

軟體供應鏈攻擊與授權合規是現代資訊採購的標準要求：

> 廠商交付之軟體應隨附並於契約維護：
> - **SBOM（軟體物料清單）**：交付物所含開源 / 第三方元件清單與版本，供機關掌握成分與風險。
> - **授權合規（license compliance）**：所用開源元件之授權型態揭露，確保不牴觸機關使用 / 散布需求（與 G 智財歸屬連動，避免 copyleft 污染機關自有程式）。
> - **相依弱點修補 SLA**：對已知漏洞（含開源相依）之修補時限（如 critical 於 N 日內）；提供弱點掃描 / SCA 報告。
> - **容器 / 映像掃描**：以容器交付者，映像須通過弱點掃描並移除高風險項目後始得部署。

- **為何放進 RFP**：得標後才發現元件授權不相容或帶已知漏洞，補救成本極高；SBOM 與修補 SLA 把供應鏈風險前移到投標即可檢核。

## S. 資通系統委外資安事項（《資通安全管理法》§10、施行細則 §7）

公務機關或特定非公務機關委外辦理資通系統之建置、維運或資通服務時，應選任適當受託者、要求其建立有效之資通安全管理機制並監督實施，且應簽訂書面契約載明權利義務及違約責任。施行細則第 7 條列出選任及監督時應注意事項，下列條款逐項對應：

> 廠商辦理本案應符合下列要求，並於建議書說明執行方式：
> - **資安人力**：配置充足且經適當資格訓練、擁有資通安全專業證照或具類似業務經驗之資通安全專業人員。
> - **複委託**：本案☐不得複委託　☐僅得就【範圍】複委託予【對象條件】；複委託之受託者應具備同等資通安全維護措施。
> - **安全性檢測**：客製化資通系統開發應提供該系統之安全性檢測證明；涉及非自行開發之系統或資源者，應標示其內容與來源並提供授權證明。
> - **事件通報**：違反資通安全相關法令或知悉資通安全事件時，應立即通知機關及採行之補救措施。
> - **終止處理**：委託關係終止或解除時，返還、移交、刪除或銷毀履約持有之資料（連動 J 節）。
> - **稽核**：機關定期或於知悉可能影響本案之資安事件時，得以稽核或其他適當方式確認執行情形，廠商應配合。

- **第三方檢測的金額門檻**：該系統屬委託機關之**核心資通系統**，或**委託金額達新臺幣 1,000 萬元以上**者，**委託機關應自行或另行委託第三方進行安全性檢測**。這筆工作與預算在機關側，不能只寫給得標廠商。
- **涉及國家機密者**：執行人員應接受適任性查核並依《國家機密保護法》管制出境；此情形**應記載於招標公告、招標文件及契約**，查核前應經當事人書面同意。
- **評選對應**：工程會《資訊服務採購評選項目及配分權重範例》將含資安人力、資訊安全及保密規劃列入子項，並要求投標廠商依行政院〈資通系統籌獲各階段資安強化措施〉附件填具資安管理作業自我評估表；價格子項含 SSDLC、資安檢測、弱點修補等費用的完整性。
